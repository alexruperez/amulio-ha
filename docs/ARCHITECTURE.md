# HAOS app architecture

## Runtime

The production app will be a single, multi-architecture image. It starts and supervises:

1. `amuled`, with configuration and downloads in `/data`;
2. `amuleapi`, bound only to the app-private network namespace;
3. aMulio, listening on its app HTTP port and using the same `/data` tree.

The app does not mount the Docker socket and does not run Docker Compose. It does not need Home Assistant Core or Supervisor API access to serve the addon.

## Storage

| Purpose | Default location | Backup policy |
| --- | --- | --- |
| aMule configuration | `/data/config` | included |
| aMulio state/database | `/data/amulio` | included |
| completed downloads | `/data/incoming` | user choice; excluded by default when large |
| incomplete downloads | `/data/temp` | excluded |

Optional finished-media mappings must never make `/data/temp` readable by aMulio playback routes.

## URL model

- **Ingress URL:** administrator-only configuration/status surface through Home Assistant.
- **Stremio addon URL:** private bearer-capability manifest URL generated by aMulio. This must be based on a user-supplied reachable public/LAN origin, never on the Ingress route.
- **Playback URL:** signed and short-lived route under the same Stremio origin.

## Network

- EC and amuleapi have no host-published ports.
- Peer ports are disabled by default and may be enabled deliberately in app options.
- A public HTTPS origin is optional for remote Stremio usage; Cloudflare Tunnel and a user-managed reverse proxy are planned options. No broad Cloudflare API token is accepted.
